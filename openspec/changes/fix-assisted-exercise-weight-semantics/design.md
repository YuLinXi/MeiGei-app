## Context

现有 `WorkoutSet.weightKg` 被所有动作共用，统计入口分散在周统计、历史、肌群、海报、Team 摘要和 BadgeEngine。计划处方和自适应回写还会按最大重量选择代表值。根据 proposal，本次不增加可配置重量模式，而由动作稳定代码提供固定语义。

## Goals / Non-Goals

**Goals:**

- 在一个可复用的动作语义判断处集中识别 `ASSISTED_PULL_UP`。
- 让所有吨位、PR、计划代表值和展示入口复用同一判断，避免各算一套。
- 不改写历史正数重量；只改变派生统计和展示含义。
- Team 摘要补足动作身份，保持现有聚合整树、LWW、幂等和共享计划去重/剥离重量约定。

**Non-Goals:**

- 不扩展弹力带、凳上辅助、TRX 等非公斤助力动作的换算。
- 不新增数据库重量模式字段；不支持自定义动作选择辅助模式。
- 不改变普通动作的统计、迁移或成就规则。

## Decisions

1. **固定动作语义**：新增集中式 `isAssistedWeight` 判断，首期只命中 `ASSISTED_PULL_UP`，不按中文名称模糊匹配。理由是稳定、可测试且不误伤“辅助胸拉伸”等动作；备选是给每个动作增加可配置枚举，但会扩大同步和迁移面。
2. **统计投影而非改原始值**：保留 `weightKg` 正数，在 `WorkoutSetStatEntry` 或等价统计投影中提供普通负重贡献与展示语义。辅助动作负重贡献为 0，组/次仍来自原始记录。理由是历史可追溯；备选是写负数，会污染存储和旧客户端。
3. **辅助 PR**：采用 spec 中的双条件比较：本次必须减少某次历史辅助且次数不降低，同时不能被另一条历史成绩覆盖。只比较本场之前的有效历史，每动作每场至多一次；首次建基线，同辅助仅增加次数不计重量突破。摘要最低辅助同值时取次数更多、再取日期更近的记录；曲线每次训练展示最低辅助并明确标注下降方向。备选是简单取最小值，会被低次数记录误导。
4. **计划与摘要语义**：计划项仍保存正数建议重量，展示层按动作语义渲染“辅助”；动作替换时只按目标动作历史复用，禁止跨语义继承。Team 摘要补充 builtin code；服务端不依赖客户端显示名称。
5. **成就重建**：用一次性规则版本标记驱动；先后台计算全量新授予，再在主上下文一次保存中替换旧 BadgeGrant，保存成功后更新版本和缓存。失败回滚且保留重试资格；账号切换丢弃旧结果，不能覆盖新会话。升级后恢复正常永久授予语义，不能每次启动清空。因为成就尚未发布，只在这次规则切换允许移除错误授予。

## Risks / Trade-offs

- [Risk] 分散统计入口遗漏 → [Mitigation] 建立统一统计 helper，并为首页、历史、Team、海报、徽章各加辅助混合训练测试。
- [Risk] 旧 Team 客户端忽略动作代码 → [Mitigation] 新字段可选、旧客户端继续显示原始摘要；新客户端只对稳定代码启用辅助展示。
- [Risk] 辅助 PR 低次数误判或重复突破 → [Mitigation] 同时检查可被本次改善的旧成绩及已经覆盖本次的历史成绩。
- [Risk] 计划摘要仍写“最重组” → [Mitigation] 辅助动作使用最低辅助代表值，并保留完整逐组预览。

## Migration Plan

1. 先发布客户端代码和测试，使用稳定动作代码识别辅助语义。
2. 规则版本落后时先计算再原子替换成就存根并刷新缓存；重复启动不再次清空，训练原始数据不变。
3. Team 新摘要携带动作代码；服务端只需透传 JSON，无数据库迁移。
4. 回滚客户端时保留正数重量和旧摘要字段；不执行破坏性数据迁移。

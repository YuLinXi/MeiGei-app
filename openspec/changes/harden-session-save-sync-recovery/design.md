# Design

## Context

动机见 proposal。现有 SessionStore 以可空门控驱动画像路由；RootView 内重试后没有失败状态。SyncEngine 逐域捕获异常并在成功落盘后提交水位，但没有可见的周期结果。普通新建计划已具备可靠保存反馈，已有计划编辑与训练提交尚未统一处理异常。

## Goals / Non-Goals

让用户识别失败并恢复，保留原训练语义和已输入内容。使用现有 SwiftData、SessionStore、SyncEngine、Paper 组件及原生 Button，不引入状态管理或持久化依赖。

数据身份、UUID、幂等键、serverId/localId/updatedAt/deletedAt/version、LWW 与软删除不变。结果状态只存在内存，不新增同步字段或数据库迁移。

## Decisions

1. **画像恢复放在会话层。** 由 SessionStore 管理有限重试和失败状态，RootView 只展示进度/恢复入口。会话代数隔离旧请求。相较仅在 View 中增加布尔值，这使重试、取消和旧响应有可测试边界；不新增通用加载状态框架。
2. **同步结果按周期记录。** 复用各域已有成功时间，收集失败域及最终本地保存结果；保留单域失败继续处理与原水位顺序。资料页说明“上次”结果，避免后续新编辑出现时误称全部已同步。切换会话清除旧结果，旧周期不得发布旧提示。
3. **用户错误与诊断信息分离。** APIError 的用户描述依据错误种类/状态码生成；日志保留诊断，不直接将服务端正文作为界面文案。不在通用错误中承诺记录已落盘。
4. **明确提交边界处理异常。** 已有计划保存与删除使用 do/catch，成功后才退出。训练高频保存继续合并，失败保留内存输入并提供重试。训练结束以专用领域提交步骤收束，先保证可靠保存，再派发系统和共享副作用。
5. **恢复只处理本次变更。** 结束与删除失败恢复只恢复本次训练涉及字段和子树，不对共享 ModelContext 执行全局 rollback。需要通过真实可写/不可写存储测试核实 SwiftData 删除恢复与身份稳定；若框架行为不支持，先调整本地提交方案，不能牺牲内容保留。
6. **训练生命周期使用独立撤销组。** 明确提交前先处理已有变更，临时使用独占 UndoManager 登记本次结束、删除或丢弃；失败撤销该组，再恢复原 manager。训练完成和自适应回写合并为一次保存，成功后才展示回执。休息先计算结算值，保存成功后才消费事件并停止计时。真实不可写库和失败后成功重试验证 Codable 处方、递减段、关系及持久化身份恢复；不在高频输入路径创建撤销组。
7. **训练输入继续延迟 300ms 合并。** 小型保存协调器只负责取消、合并、立即保存及失败状态，成功后才发布 Live Activity 快照。错误区域持续提供重试；结束或丢弃失败的重试仍执行对应生命周期操作，不用普通保存冒充已完成。UI 故障钩子仅在 DEBUG 与隔离测试启动参数同时满足时生效，首次失败后重试走真实保存；同步行通过隔离 HTTP fixture 验证，不请求真实服务器。
8. **创建与替换训练统一提交。** 首页、个人计划和 Team 调用同一个会话入口，提交时重新核验当前活跃会话。创建候选使用同一container的短生命周期context；替换在其中一次保存旧会话墓碑与新会话。失败不将候选插入主context，原训练和主context未保存编辑保持原状；成功后镜像旧会话的墓碑，并按已保存身份在调用方context取回新训练，使后续录入仍由原保存协调器提交。成功后才展示新训练和记录 Team 使用事件。完成页另存复用防重复创建提交器，同时保存训练改名；失败只恢复这次改名与候选计划，历史详情另存仍不改原名。
9. **撤销快照先完整读取训练子树。** 实测 SwiftData 对未读取子节点进行级联删除时会触发 `_FullFutureBackingData` 快照崩溃，软删除的撤销也可能还原为空关系。训练生命周期提交前读取本聚合的动作/组持久化属性；不扫描完整历史，不加入高频输入热路径。保留未读取子树、待确认／已同步会话替换及真实不可写库回归。`LocalModelCommit` 只是复用短同步提交步骤，不创建新持久化框架。
10. **剩余提交入口按含义处理。** 自定义动作和资料编辑失败保留草稿或可恢复状态；回写撤销可靠保存后才关闭回执。身份迁移只在读取与所需保存成功后写完成标记，失败恢复本次改挂字段，保留快速跳过已完成迁移的路径。资料首登提交的迟到响应按会话代数丢弃。
    自定义动作创建另用同一 container 的短生命周期 context 保存，只在成功后返回新 ID。真实只读存储实测表明，失败插入即使撤销或显式删除，也可能暂留在原 context 查询中；隔离候选避免其进入列表或随其他编辑落盘。已有动作删除仍只撤销本次字段修改。资料上行串行合并后续编辑，旧 GET/PATCH 响应不能覆盖新值或清除新待传标记。
11. **清理与会话失效是单独验收边界。** 删号成功后先持久化清理未完成标记并退出认证，RootView 移除正常页面后再执行清理；失败保留重试门控，重启也不进入登录、同步或正常启动迁移。仅在既有八类模型清理与保存成功后清除标记和同步水位。普通退出仍保留缓存。会话层在登录/退出时同步使旧同步周期失效；每次网络返回后、应用 DTO 前、最终保存与水位提交前核对代数及会话可用性。新周期可以开始，旧周期的结束不能清掉新周期忙碌状态。隔离库、真实只读库、受控旧推送/拉取和 UI 故障重试均已覆盖；没有执行真实删号或清理日常缓存。
12. **丢弃已保存训练保留删除墓碑。** `serverId == nil` 只表示尚未确认，不能证明服务端未收到在途创建。丢弃与原子替换均使用现有 `markDeleted()`，让迟到响应识别更新后的删除意图，后续同步按原 localId 推送墓碑，确认后沿用既有本机清理。直接丢弃失败仍由撤销组恢复原会话和子树；替换失败的候选随独立context销毁，主context不参与失败插入。真实只读库实测中，在主context撤销后再次显式删除仍有20/20轮返回失败候选，因此不能以撤销和清理调用本身证明内容已恢复。独立 SQLite 与受控上传响应分别验证直接丢弃、替换、失败重试和重开容器；不新增请求队列、同步字段或后端接口。
13. **计划与分组候选隔离提交。** S6真实只读SQLite回归中，普通新建与完成页另存各10/10轮在显式删除后仍返回失败候选。新建／另存／复制计划与新分组改用 `LocalModelCommit.insert`，在同一container的短生命周期context中保存，成功后按持久化身份返回调用方context的模型。其他未保存输入继续留在调用方，不被顺带保存或回滚。完成页重新读取已保存的来源训练，在候选context内将训练改名与新计划一次保存；成功后才镜像主context的名称与信封。来源失效保留明确错误，历史另存不改名，防重复提交继续由原提交器负责。
14. **明确保存使用项目变更事件。** 同一原生探针在iOS17.4保存后没有收到`ModelContext.didSave`，26.5会收到，导致旧系统的徽章缓存不刷新。明确保存入口统一调用小型`LocalModelSave`函数：保存前捕获插入、修改和删除标识，可靠保存后发布项目事件；新增／修改标识在成功后读取永久身份，删除标识在保存前保留。徽章及计划页订阅项目事件，避免与新系统原生事件重复。保留原context归属过滤、进行中训练不重读完成历史及300ms合并；不拦截框架自动保存，不改变数据结构、同步协议或保存失败恢复。
15. **来源失效检查先于子树读取。** iOS17.4的完成页另存回归捕获到：未落库训练先进入`planTemplateItems()`，读取尚未稳定的组到动作逆关系时触发SwiftData trap，原有独立context来源检查尚未执行。入口先拒绝无context、已删除或仍在所属context插入集合中的来源，再沿用原处方提炼和独立context检查；返回既有`sourceUnavailable`，不通过额外保存来源消除错误。
16. **未展开子树也必须完整恢复。** iOS17.4独立回归中，结束训练清理未完成组后注入保存失败，训练恢复进行中，但尚未展示过的动作和组变为空。调试器确认节点已撤销删除、仍属于原context且数值保留，但两层关系都为空，单纯延长引用生命周期无效；局部重新连接原节点关系可恢复。生命周期提交前记录当前动作及各动作的组引用，原Undo仍负责字段撤销，失败后只补齐这份聚合关系；恢复时暂时关闭undo注册，避免将失败恢复变成调用方的新撤销项。不重建身份、不全局回滚、不额外保存，其他未保存编辑及错误反馈仍保留。

17. **相同身份的同步子节点原位更新。** 最低系统完整回归与独立复现均发现：连续下拉相同动作／组ID时，删除旧子树再新建相同唯一ID的节点，会使已保存聚合缺少组关系；同步结束后新读取器仍能读到缺失，因此不能仅调整读取调度。应用完整服务端聚合时按ID复用已有动作和组，更新全部同步字段，只删除响应已移除的节点。远端内容仍作为整体裁决，不做字段冲突合并；保留未推送保护、LWW、受控批次和最终水位边界。回归继续核对每个动作的组数与最终独立读取，不以总根数量或无崩溃代替完整性。

18. **已有计划的失败草稿留在表单。** 名称、备注、模式与分组由现有表单状态持有；基础信息提交复用 `LocalModelCommit.perform`，失败只撤销本次字段与同步标记，保留其他未保存内容。取消继续关闭表单，后续自动保存或其他页面保存不会提交已经取消的草稿。用独立SQLite覆盖失败后取消、另一计划保存及重开存储，并用实际表单验证失败输入与重试仍可用；不把训练高频输入的保留策略扩展到明确取消的计划表单。

## Risks / Trade-offs

- 异步旧画像响应覆盖新账号 → 会话代数在每个挂起边界之后核对，退出/登录时重置恢复状态。
- 本地保存失败与网络失败混淆 → 周期结果单列本地落盘失败，不显示“已保留在本机”的不实保证。
- 失败恢复改变训练结构或触发历史重建 → 定向测试验证子树、未完成组、其他编辑和读取计数；保留原输入合并与快照架构。
- 新错误状态增加重复提示 → 用当前错误区域/资料同步行呈现，后台周期不连续弹窗。
- 测试污染私人记录 → 使用内存或独立测试库与 HTTP fixture，不抹除日常缓存、不上传合成训练。

## Migration Plan

先验证故障用例，再按画像、同步、明确保存边界实施；每批运行相关定向测试，UI 用例复用固定模拟器串行执行。无后端部署、配置或数据库迁移。回退对应 iOS 变更即可，历史数据结构不改变。整体准发布仍需专项其余批次和真机证据。

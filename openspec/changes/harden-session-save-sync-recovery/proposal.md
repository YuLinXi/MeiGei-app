# Proposal

## Why

UI／UE 专项审查确认：画像重试耗尽后缺少恢复入口、同步失败后只显示“空闲”、部分本地保存异常被成功流程掩盖。这些问题使用户难以判断训练是否可靠保留，需要在准发布前修复。

## What Changes

- 为画像路由增加有限重试后的失败状态、重新尝试和返回登录入口，保留已有本地画像的离线进入行为。
- 记录同步各域与本地落盘的本轮结果，在“我的”中区分上次成功、部分失败与失败，提供可理解的重试提示。
- 统一面向用户的网络错误表达，不直接展示 HTTP body、JSON 或解码异常。
- 修复训练提交、已有计划编辑及相关删除路径的保存异常处理；失败保留本次内容，不执行成功退出、分享或归档副作用。
- 覆盖个人计划的处方、模式、移组、分组、复制、删除及完成页另存；开始新训练与替换旧训练按一次可靠提交处理，失败不丢弃旧会话或进入未落盘记录。
- 统一自定义动作与资料编辑的明确提交反馈，补齐回写撤销、历史动作身份迁移完成标记及删号本机清理的失败恢复；失效会话的画像写响应和同步响应不得覆盖当前会话或回填已清理数据。
- 保留训练输入的 300ms 保存合并、聚合同步、LWW、水位提交顺序与隐私边界。
- 修复上传在途时丢弃或替换训练会恢复旧会话的问题；尚未收到 serverId 的训练也保留可重试的删除墓碑，沿用现有同步协议。
- 统一明确本地保存后的变更事件，使最低系统与当前系统均刷新相关缓存；保存失败不发送成功事件，进行中训练的普通保存不触发完整历史重读。
- 修复连续下拉同一训练后动作与组关系缺失的问题，保持相同子节点身份和完整聚合内容，并继续保护尚未推送的本地修改。
- 核验已有计划基础信息保存失败后的取消边界，保留表单草稿供重试，并防止已取消字段随其他保存意外落盘。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `profile-ui`：画像加载失败的恢复与资料页同步结果反馈。
- `account-sync`：同步结果可见性和用户错误表达。
- `workout-tracking`：训练及计划提交失败时的内容保留和成功副作用门控。
- `exercise-library`：自定义动作提交与历史身份迁移的可靠完成。

## Non-goals

不更换 Paper 设计体系，不增加登录提供方，不修改 Team 默认共享偏好，不扩展训练模式，不恢复饮食模块，不引入后端接口、数据库迁移或通用持久化框架。大字号、全产品布局与帧级性能验收继续由专项后续批次完成。

## Impact

影响 RootView、SessionStore、SyncEngine、APIClient、ProfileView、训练/计划的提交边界及相应测试。没有后端、依赖或基础设施变更；发布前仍需验证真实交互与性能未回退。

## Why

普通动作和递减组的默认休息目前只保存在单次 `WorkoutUnit`，训练完成后不会进入来源计划；下次从计划开始训练时，组数、重量和次数能够带入，动作默认休息却重新回退全局设置。用户因此需要在每次训练中重复配置，且计划详情无法完整表达下一次实际执行安排。

## What Changes

- 为普通动作和递减组计划项保存可选默认休息，语义与现有 `WorkoutUnit.restAfterSetSeconds` 一致：缺失为跟随全局、`0` 为关闭自动休息、正整数为显式秒数。
- 从个人计划或 Team 计划开始训练时，把计划默认休息落入对应训练单元；超级组继续复用现有轮后休息字段。
- 自适应计划完成训练后，把本次训练单元中显式配置的默认休息与组数、重量、次数一起回写，并纳入回写回执与撤销；严格计划继续不回写。
- 计划编辑与详情展示默认休息，并允许用户在“跟随全局”“关闭”“常用秒数”和自定义秒数之间切换。
- 保存为计划模板、计划复制、Team 分享/Fork 等既有计划转换路径保留默认休息。
- 继续将每组预计休息与实际休息只作为训练历史事实保存，不使用真实休息用时或单次倒计时调整自动学习计划默认值。

## Non-goals

- 不新增逐组休息处方；一个普通动作或递减组训练单元只保存一个默认休息。
- 不根据 `actualRestSeconds`、单次 `+/-` 调整或训练历史统计自动推荐休息时长。
- 不改变现有组内休息继承优先级、提醒、Live Activity、本地通知或全局默认休息设置。
- 不新增后端表、独立 API、同步实体或第三方依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workout-tracking`: 扩展训练计划的开始预填、自适应实绩回写、计划详情与计划转换规则，使默认休息和既有组数、重量、次数一起跨训练保留。
- `team-sharing`: Team 分享快照、Fork 与直接开始训练保留休息配置，同时继续剥离作者重量。

## Impact

- iOS 计划模型：`PlanItem` JSON 增加可选默认休息字段，旧计划缺失字段时保持兼容。
- iOS 训练链路：计划构建、计划编辑/详情、自适应回写回执、保存为模板、复制及 Team 分享转换需要传递该字段。
- 同步边界：继续复用 `WorkoutPlan.items` jsonb 与既有 LWW 同步信封；后端只透明保存 JSON，无 schema 或 API 变更。
- 测试：补充旧 JSON 兼容、计划开始落值、模式边界、休息单独变化的回写/撤销及所有计划转换路径覆盖。

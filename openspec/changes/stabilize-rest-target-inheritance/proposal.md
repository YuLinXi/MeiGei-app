## Why

训练中下一组休息目前继承的是上一组启动计时时写入的初始预计值；用户在休息过程中通过 `+10s / -10s` 调整目标后，最终目标没有回写，导致后续组继续使用旧时间。普通动作的统一休息配置又只保存在页面 `@State`，页面重建后可能丢失，最终形成界面配置、实际计时和下一组继承不一致。

## What Changes

- 将 `WorkoutSet.plannedRestSeconds` 明确定义为该组休息结束时的最终目标总时长；自然结束和提前结束都保留最终目标，`actualRestSeconds` 继续记录实际流逝时间。
- 下一组休息按固定优先级解析：同一动作紧邻上一组已完成休息的最终目标 > 当前动作默认休息配置 > 用户全局默认配置 > 90 秒系统兜底；同一动作包含热身组、正式组和递减组父组。
- 在完成新组前先收束上一段活动休息并回写最终目标与实际时间，再解析和启动新一段休息，避免读取尚未落盘的旧目标或遗留旧倒计时。
- “继续休息”按同一组的追加休息处理，最终目标和实际时间分别累计；超级组在轮级采用“上一轮最终目标 > 轮后休息配置 > 全局默认 > 90 秒”的对应规则。
- 将普通动作的默认休息配置保存到既有 `WorkoutUnit` JSON，使最小化、页面重建和同步后仍可恢复；菜单文案从“统一休息”收敛为“默认休息”，与其回退语义一致。
- 更新休息策略单元测试和训练页回归场景，覆盖调时、提前结束、继续休息、配置回退、热身转正式与超级组轮级继承。

## Non-goals

- 不新增普通动作计划模板的休息处方字段，不改变跨场训练的计划预填与自适应回写。
- 不根据 `actualRestSeconds` 自动学习或推导后续休息目标。
- 不改变休息提醒声音、震动、本地通知、Live Activity 展示和训练结束归档规则。
- 不新增后端表字段、Flyway 迁移或独立休息实体；继续复用 workout 聚合中的 `units` JSON 与现有组休息字段。
- 不新增“将本次 `+10s / -10s` 应用到全部后续组”等额外交互。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workout-tracking`: 修正组间休息最终目标回填、同动作/超级组继承优先级、活动休息收束顺序和动作默认休息配置的持久化要求。

## Impact

- iOS 领域模型：`WorkoutUnit` 增加向后兼容的可选动作默认休息字段，继续经 workout `units` JSON 保存和同步。
- iOS 休息运行时：`RestTimerController.CompletionEvent` 的既有时间字段用于派生最终目标，训练页消费事件时同时回写预计与实际休息。
- iOS 训练页：普通动作和超级组完成路径、继续休息累计逻辑、休息菜单读写及文案调整。
- 测试与规格：更新 `WorkoutRestPolicyTests` 及 `workout-tracking` 增量规格；无新依赖、无后端 schema 变更。

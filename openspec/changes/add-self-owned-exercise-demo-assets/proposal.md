## Why

动作库原本以单列小图行展示动作，通用肌群图和实际动作图都难以清楚表达人物、器械与姿势。此前 Blender/GIF 方案的制作成本与视觉结果不匹配，因此改为只生产高质量静态动作图：以一个原创统一角色为长期视觉主体，通过 AI 生成并按项目所有者明确授权的自治审核策略逐张审核 288×288 图，再以右侧双列紧凑图卡片渐进替换列表中的肌群缩略图。

## What Changes

- 废止本 change 中 Blender、骨骼绑定、器械动画、12 帧、GIF 播放和 Reduce Motion 动态降级方案，静态图成为唯一交付媒体。
- 建立一个原创虚构男性角色的身份母版与视觉规范，锁定脸型、发型、体型比例、服装、解剖线稿、肌肉高亮、色板、背景和构图语言。
- 新动作图必须以已批准的角色母版和风格母版作为 imagegen reference/edit 输入生成，不允许仅靠文本 prompt 独立重造人物。
- 将此前批准的“效果图 1”——顶部横梁式常规蝴蝶机、45° 构图、灰阶人体、胸大肌朱砂红高亮——作为 `PEC_DECK_FLY` 的视觉验收基准；母版原始暖白底在正式导出时统一归一为纯白，正式资产仍须在新流程中完成来源记录、角色一致性和动作/器械审核。
- 每个动作保留一个已批准的高分辨率静态母版，并确定性移除烘焙暖色背景、导出纯白底 288×288、JPEG 质量 82、单张不超过 24 KiB 的 sRGB JPG；候选图、失败图和临时生成物不进入版本控制。
- 以稳定 `BuiltinExercise.code` 建立静态资产 manifest、文件命名、来源台账、人工审核和自动校验；只允许已批准条目进入 App。
- 动作库右侧动作区改为按原解剖层级分段的双列小尺寸图卡片；卡片不撑满可用列宽，单卡在当前 iPhone 上最大约 104pt。卡片上部使用占比更高的白色媒体底，图片等比放大并保留安全边距；下部以更紧凑的小字号显示动作名，把主要空间留给动作图。尚无已批准图片、资源损坏或映射失败时继续显示带更大留白的现有肌群缩略图或首字占位。
- 首个动作与代表动作已验证标准后，按项目所有者授权的自治审核策略持续覆盖全部内置动作；无唯一标准或无法稳定满足质量规则的动作记录并跳过，不阻塞其余动作。

## Capabilities

### New Capabilities

- `exercise-demo-assets`：定义原创统一角色、AI 静态动作图、来源与权利边界、人工审核、288×288 导出、版本控制和分阶段扩量。

### Modified Capabilities

- `workout-tracking`：动作库内置动作行从“肌群图优先”调整为“已批准的实际动作图优先”，并保留现有降级行为。

## Impact

- **素材生产**：使用 imagegen 生成单张静态母版，不再依赖 Blender、动画编码器或 GIF 运行时。
- **版本控制**：未来只保存角色/风格母版、已批准动作母版、prompt/brief、来源台账、manifest、导出脚本和 288×288 正式 JPG；大尺寸已批准母版按实测决定是否使用路径限定的 Git LFS。
- **iOS**：未来在 `ExerciseLibraryContentView` 的双列动作卡片中按 code 加载本地静态图；不增加远程下载或第三方图片运行时。
- **数据边界**：不修改后端、数据库、同步信封、训练记录、计划、Team 或动作分类数据。

## Non-goals

- 不制作 GIF、视频、APNG、SVG 动画、逐帧图片、交互式 3D、Blender 模型或骨骼动画。
- 不降低质量去凑齐全部 224 个内置动作；先用已验证动作锁定标准，再按动作族持续覆盖，争议或不合格项必须记录并跳过。
- 不声称 imagegen 能自动保证同一人物；角色一致性必须通过参考图生成、可比对的验收项和自治或人工拒绝门槛保证。
- 不复制、下载入库、转描、风格迁移或把 `hasaneyldrm/exercises-dataset` 的图片作为生成输入；只可参考不受版权保护的动作与常规器械事实。
- 不替换动作详情页的 `MuscleMapView`，不改变自定义动作的数据模型，不为自定义动作按名称猜测内置图片。
- 不引入 CDN、运行时生成、用户上传、后台素材管理或新后端 API。

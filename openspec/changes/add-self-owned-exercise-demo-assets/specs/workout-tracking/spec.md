## MODIFIED Requirements

### Requirement: 动作库（ExerciseLibrary）版式

`ExerciseLibraryView` SHALL 采用**训记式左栏版式 + 解剖三级树导航**：导航栏（标题「动作」+ 右上 `+`）+ 搜索框（占位「搜索 {N} 个动作」，N=去噪后内置+自定义合计）下方，主体分**左栏部位轴**与**右侧动作区**两栏。

**左栏（解剖树，竖排）** SHALL 固定窄宽竖列：顶部「全部」「我的（自定义）」+ 全部 11 个 L1 部位，每项带数量角标；超屏自身可纵向滚动。有下级的节点 MUST 支持**逐级就地手风琴展开**：L1 展开 L2，L2 再展开 L3，点哪一级即过滤到哪一级。若某 L1 只有一个 L2 且该 L2 有 L3，UI SHALL 折叠这个唯一 L2，直接展示 L3（如「胸→上胸/中下胸」「肩→前束/中束/后束」），但内部筛选仍使用完整 L2/L3。无下级的节点 MUST NOT 展开。**MUST NOT** 以独立横滚 chip 行承载部位/肌肉/肌头任一级。

**右侧动作区** SHALL 顶部渲染**器械轴** `HorizontalChipPicker`（`EquipmentType`），与解剖树**正交叠加**；下方动作列表按**解剖树层级分段**：选「全部」按 L1 分段，选某 L1 按其 L2 分段，选某 L2 按其 L3 分段（无下级则平铺）。若该 L1 命中单一 L2 折叠规则，则选 L1 后直接按 L3 分段。**MUST NOT** 使用「复合推/拉/腿/单关节」等动作模式分组。同段内 curated 内置动作 SHALL 优先排序。

右侧动作区 SHALL 使用固定两列的 `LazyVGrid` 小尺寸图卡片，现有解剖层级分段 header 横跨两列。同一设备内两列等宽、间距一致并在右侧内容区居中；单卡使用 88–104pt 的受限弹性宽度，在当前 iPhone 上最大约 104pt，不得撑满全部可用列宽。卡片上部为约 1.25:1 的响应式白色媒体区，图片底部保留 4pt 间距并使顶部留白大于底部留白；下部为最低 26pt、从顶部排版、最多两行且居中的 12pt 中文动作名，单行动作名到底边的留白 MUST 保持紧凑。卡片整体 SHALL 为单一点击目标并满足至少 44pt 触控高度。内置动作存在以稳定 `BuiltinExercise.code` 映射、审核通过且文件完整的 288×288 静态动作图时，媒体区 MUST 优先显示该动作的实际人物、器械与姿势；图片 MUST 等比完整显示并保留安全边距，运行时 JPG MUST 使用纯白背景，沿用别练了统一原创角色与自绘纸感风格，MUST NOT 引入第三方写实解剖线稿。没有正式动作图、映射失败或文件损坏时，媒体区 MUST 以相同几何继续显示现有部位图，并为肌群图保留比正式图更大的四周留白；肌群 PNG 的原烘焙背景 MUST 转为透明，使其直接融合进白色媒体区，避免局部人体贴边放大或出现粉色方块。部位图也不可用时 SHALL 显示首字占位。自定义动作不按名称猜测内置图片，其首字占位也使用相同卡片结构，避免有图与无图的布局跳变。

卡片 SHALL 沿用现有暖白纸感、边框、圆角和朱砂红体系，不复制参考产品的亮蓝色、“讲解”角标或器械重复分组。动作名、分段标题、器械快速索引和详情页共同提供归属信息，卡片常态不再显示旧行式部位/器械副标；未来存在 PR 时可在卡片内以不遮挡主体的小标签显示。browse、search、pick 共用同一卡片，browse 模式自定义动作仍支持长按删除，pick 模式不得触发删除。

正式动作图 SHALL 为随包本地静态资源，动作列表 MUST NOT 发起网络请求、调用 AI、加载高分辨率母版或解码任何动态媒体。browse 与 pick 模式复用同一内置动作图规则。图片仅作装饰并对 VoiceOver 隐藏，卡片合并朗读动作名与可用归属信息，并保留按钮、长按删除和选择语义。

自定义动作行在动作库 browse 模式 SHALL 提供手动删除入口。该入口 MUST 通过长按自定义动作行触发，并直接展示二次确认；常态行内 MUST NOT 展示删除图标、`-` 控制或滑动删除按钮，行右侧最新 PR 数值 MUST 继续保持靠右展示，不被删除入口挤占。确认后客户端 MUST 将该 `CustomExercise` 写入软删墓碑（`deletedAt` 非空、`syncStatus=pendingDelete`）并通过现有同步流程上传。删除后的自定义动作 MUST 从动作库与后续动作选择器隐藏。删除 MUST NOT 级联删除或改写既有历史训练、已有计划项或 Team/计划快照中的动作引用与名称快照。动作选择器 pick 模式 MUST NOT 在自定义动作行展示删除入口，且 MUST NOT 响应长按删除，以避免选动作时误删。

新建自定义动作弹窗 SHALL 使用紧凑底部 sheet：顶部只展示拖拽 handle 与居中标题，不展示左上角取消按钮；sheet 高度 SHALL 按内容自适应，避免固定高度造成大块顶部留白。表单 SHALL 包含动作名称输入、部位标签网格和器械标签网格；部位标签 MUST 来自 `ExerciseCategory.allCases`，器械标签 MUST 来自 `EquipmentType.allCases`，与动作库左栏与器械轴同源。动作名称 MUST 为必填；部位和器械可不选，保存时保持为空值，列表副标以缺省符号展示。

搜索框 SHALL 做**中文模糊匹配**：query 按空格拆为关键词，名称 MUST 包含**全部**关键词（顺序无关、大小写不敏感）方为命中。MUST NOT 实现拼音、英文 code、别名、相关度排序、debounce 或预建索引。query 非空时搜索 MUST 作为**全局通道**——忽略左栏 L1/L2/L3 选择、对全库匹配、结果按 L1 分段、左栏选中态淡化；器械 chip 仍叠加。query 清空后 MUST 回到左栏当前选择的浏览态。

#### Scenario: 左栏纵览 11 部位
- **WHEN** 进入动作库
- **THEN** 左栏竖排可见「全部 / 我的」+ 11 个 L1 部位（含手臂/颈部/功能性等），各带数量角标；无需横滑发现部位

#### Scenario: 三级逐级下钻
- **WHEN** 用户点 L1「胸」展开其下级并点「上胸」
- **THEN** UI 直接显示「胸→上胸/中下胸」，右侧过滤为内部链「胸→胸大肌→上胸」命中者；点无下级的节点（如 L2「背阔肌」）不再展开、右侧平铺该 L2

#### Scenario: 右侧按树层级分段
- **WHEN** 用户在左栏选 L1「胸」
- **THEN** 因「胸」只有一个 L2 且有 L3，右侧直接按「上胸/中下胸」分段；选「全部」按 L1 分段；多 L2 部位仍先按 L2 分段；**不**出现「单关节」等动作模式伪分组

#### Scenario: 器械轴正交叠加
- **WHEN** 左栏选「胸 → 上胸」、器械轴选「哑铃」
- **THEN** 右侧过滤为内部命中「胸→胸大肌→上胸」且 `equipmentType=="哑铃"` 者；任一轴留「全部」则该轴不约束

#### Scenario: 已批准动作图替换肌群缩略图
- **WHEN** 动作库渲染已有正式静态图的 `PEC_DECK_FLY`
- **THEN** 双列卡片的白色媒体区等比完整显示统一角色操作常规蝴蝶机的对应 288×288 实际动作图
- **AND** 不再为该卡片显示通用胸部肌群缩略图

#### Scenario: 双列卡片统一展示
- **WHEN** 动作卡片分别显示正式动作图、肌群降级图或首字占位
- **THEN** 三种状态都占据同一个 88–104pt 卡片内、约 1.25:1 的白色媒体区，图片顶部留白大于底部留白并靠近标题
- **AND** 正式动作图与肌群降级图都等比完整显示且不贴边，肌群图使用更大的安全边距
- **AND** 正式动作图为纯白底、肌群降级图背景透明，二者都与白色媒体区无可见色块边界
- **AND** 动作名在卡片底部以 12pt 居中显示、最多占两行，且单行动作名到底边保持紧凑留白
- **AND** 整张卡片作为单一点击区域，网格切换筛选时不发生结构跳变

#### Scenario: 未覆盖动作安全降级
- **WHEN** 内置动作没有运行时条目、图片缺失或图片无法解码
- **THEN** 动作行继续显示现有肌群缩略图
- **AND** 肌群缩略图也不可用时显示名称首字，不出现破图或空白

#### Scenario: 搜索和选择器共用静态图
- **WHEN** 同一已覆盖动作出现在浏览、搜索结果或 pick 模式
- **THEN** 各入口按同一 code 显示同一张本地静态动作图
- **AND** 列表不发起网络请求或加载动态媒体

#### Scenario: 自定义动作不猜测图片
- **WHEN** 自定义动作名称与某个内置动作相同或相近
- **THEN** 系统不复用内置动作图
- **AND** 自定义动作继续使用现有部位图或首字占位

#### Scenario: 自定义动作入口与并段
- **WHEN** 用户点左栏「我的」
- **THEN** 右侧只显示未删除的自定义动作；改选某具体部位时，该部位下的自定义动作按 `primaryMuscle` 并入对应段

#### Scenario: 手动删除自定义动作
- **WHEN** 用户在动作库 browse 模式长按某自定义动作行并确认删除
- **THEN** 客户端将该自定义动作标记为软删墓碑并保存为待同步删除
- **AND** 该自定义动作从动作库列表消失

#### Scenario: 删除自定义动作后保留既有引用
- **WHEN** 自定义动作已被删除
- **THEN** 历史训练、已有计划项和 Team/计划快照中原有的动作引用与名称快照保持不变
- **AND** 后续打开动作选择器时不再显示该已删除自定义动作

#### Scenario: 选择器不展示删除入口
- **WHEN** 用户从训练或计划编辑流程打开动作选择器
- **THEN** 自定义动作行可用于选择动作
- **AND** 行内不展示删除入口
- **AND** 长按自定义动作行不会触发删除确认

#### Scenario: 新建自定义动作标签分类
- **WHEN** 用户从动作库右上角 `+` 打开新建自定义动作弹窗
- **THEN** 弹窗顶部无左上角取消按钮且留白紧凑
- **AND** 部位以 `ExerciseCategory` 标签网格选择，器械以 `EquipmentType` 标签网格选择
- **AND** 保存后自定义动作按所选部位和器械参与动作库筛选

#### Scenario: 中文模糊多关键词搜索
- **WHEN** 用户输入「杠铃 卧推」（或「卧推 杠铃」）
- **THEN** 命中名称同时含「杠铃」与「卧推」者（如「平板杠铃卧推」），顺序无关；搜索期间忽略左栏选择、全库匹配并按 L1 分段、左栏选中态淡化

#### Scenario: 命中 PR 副标
- **WHEN** 某动作历史最佳 1RM > 0
- **THEN** 卡片以内嵌小标签显示「PR · {重量}」mono 字体，按当前单位（kg / lb）
- **AND** 标签不遮挡人物、器械或动作名

#### Scenario: 数据库空
- **WHEN** 内置动作 0 条且自定义 0 条
- **THEN** 右侧渲染单张占位卡「动作库尚未采集，点右上 + 添加自定义动作」+ CTA

# Proposal

## Why

UI／UE 专项的独立 SQLite 采样确认，5000 条历史训练下拉在主线程逐条查询已插入子树，超过 7 分钟仍未结束。批量查找后虽然能完成全量恢复，单轮仍约 21 秒且最长主线程调度间隔约 13.8 秒，需要继续改善批量应用与落盘期间的交互响应。

## What Changes

- 下拉训练先批量取得已有聚合根，避免逐条查找重复遍历待保存对象。
- 按完整训练聚合分批应用和可靠落盘，在批次之间让出主执行器，使其他交互任务有机会执行。
- 批次之间重新核验同步代数与会话；失效周期不再应用、落盘或回填旧数据。
- 保留 LWW、未推送本地编辑保护、幂等重放和所有同步信封字段；中途失败仍可重试。
- 本地批次保存失败必须反映到本轮保存结果，整轮成功落盘前不推进增量水位或发布可靠成功事件。
- 用独立 SQLite 库、隔离 HTTP fixture、调度探针和原生调用栈验证；组件结果与实际帧级、真机门禁分别记录。
- 修复并发读取崩溃：历史与勋章快照分批复制持久化字段，与训练写入串行；后台只接收值并继续聚合，不持有可能被子树替换删除的模型。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `account-sync`：大批量训练同步期间的交互响应、聚合批次提交与失败／会话隔离边界。

## Non-goals

不修改后端 API、数据库 schema、同步 DTO、训练统计口径、Team 权限或分享偏好；不增加 CloudKit、登录方式或通用持久化框架。该变更不替代整个专项的设备、帧级、能耗、真实后端与真机验收。

## Impact

影响 iOS `SyncEngine` 的训练下拉应用和本轮保存结果汇总、历史／勋章快照的字段复制，以及相应回归／性能测试。训练、动作和组的主外键与信封保持原样；没有后端部署、依赖或迁移需求。相关证据归入 UI／UE 专项 S4，不据此放行最终候选。

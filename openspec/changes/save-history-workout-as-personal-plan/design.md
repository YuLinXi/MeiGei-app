# 历史训练另存为个人计划设计

## Context

功能动机与范围见 [proposal.md](proposal.md)，可观察行为见 [规格增量](specs/workout-tracking/spec.md)。本设计需要协调历史详情、普通新建表单和既有完成页行为，因此保留独立设计文档。

当前实现依据：

- 首页最近训练与历史日历都打开 `WorkoutDetailView`。该视图只读展示训练，更多菜单目前只有海报和删除；新增入口应落在共用详情页。
- `Workout.planTemplateItems()` 已按训练单元生成普通动作、递减组和超级组计划项。普通动作包含已完成热身／正式组的 `setPrescriptions`，递减组包含各逻辑组的 segments，超级组保存轮数与成员摘要。
- `canOfferSaveAsPlanTemplate(alreadySaved:)` 专门控制完成页提示，要求 `planId == nil`。现有测试明确验证个人计划来源训练不展示该提示，不能直接放宽这个条件来实现历史入口。
- `PlanEditorView` 承载普通计划的新建／基础信息编辑，已有名称、整体备注、模式和分组，但新建分支目前不接收初始动作项。
- `WorkoutViews.swift` 中的私有 `SaveWorkoutAsPlanSheet` 使用独立表单，保存时会更新 `workout.title`、标脏训练，并以 `try?` 忽略保存失败。历史另存不能直接复用这条保存路径。
- `WorkoutPlan.items` 已以 JSON 经现有计划同步域持久化。新增历史入口不需要改变数据模型和服务端协议。

## Goals / Non-Goals

**Goals：**

- 将历史训练转换为普通新建计划的初始值，复用同一表单和创建分支。
- 明确区分转换资格、完成页提示资格与各入口的副作用。
- 让取消、失败重试、离线保存和成功反馈与独立计划语义一致。

**Non-Goals：**

- 不引入历史计划专属实体、额外来源关系、保存接口或常驻转换服务。
- 不重写普通动作／递减组编辑器，也不扩展超级组逐轮结构或改动现有预填、回写算法。
- 不借本次功能修正主规格与现有历史编辑 UI 的其他差异。

## Decisions

### 1. 历史入口与完成页提示采用不同资格

历史手动另存要求训练已完成、未软删，且经现有转换规则得到至少一个有效计划项；不要求 `planId == nil`，也不使用完成页的 `alreadySaved` 状态。保留 `canOfferSaveAsPlanTemplate(alreadySaved:)` 的当前语义，在同一转换文件中增加可测试的历史另存资格判断，必要时仅提取两者共有的基础条件。

转换只访问当前选中的训练聚合，不查询来源计划，也不扫描全部训练历史。首次点击时生成本次表单持有的初始动作值，避免视图重绘反复生成身份或异步覆盖用户输入。展示表单及确认保存前均需确保当前训练仍满足已完成、未删除的条件。

替代方案是放宽现有完成页判断，但会使个人计划训练在完成后重复展示保存行动卡，并改变已有回写回执流程，因此不采用。

### 2. 为普通新建表单增加可选初始值

扩展 `PlanEditorView` 的新建入口，使其可接收初始名称、备注、动作项及创建成功回调；现有空白新建调用默认值保持为空。历史详情传入本次训练的值，模式默认 `.adaptive`、分组默认 `nil`，沿用现有模式选择、备注规范化和组内末尾排序。

初始值只是表单持有的值，在用户保存前不插入 `WorkoutPlan`。保存时由普通新建分支把初始动作项一起写入计划；在计划列表普通新建时依然创建空动作计划。基础信息编辑已有计划的流程不根据这些初始值重建动作项。

产品上的默认细节：

- 训练标题为空、仅空白或为通用名称「训练」时，预填「训练模板」；用户可修改。
- 另存表单沿用普通新建计划的基础信息布局，动作逐组调整在保存后的普通计划详情中进行。
- 成功后关闭表单，返回原历史详情，以现有全局消息显示「已保存为『计划名』」；不自动切换 Tab 或开始训练。
- 用户之后可以再次主动另存同一训练；每次明确保存生成独立副本，不进行跨次去重。

替代方案是复制完成页表单，但会新增第二套普通新建规则，且容易继承修改历史名称的副作用；不采用。为本次单一路径引入通用草稿框架也没有必要。

### 3. 复用实际内容转换，逐组安排与摘要各司其职

以 `planTemplateItems()` 为唯一训练内容转换入口，沿用其对单个训练聚合的处理：

| 训练单元 | 转换内容 |
| --- | --- |
| 普通动作 | 至少完成一个正式组才生成计划项；带入已完成热身组和正式组的独立组类型、重量、次数，沿用热身优先及 `setIndex` 顺序 |
| 递减组 | 带入已完成逻辑组及每组自己的有序 segments，不把多个逻辑组压成第一组的副本 |
| 超级组 | 保留当前轮数、两个成员顺序、各成员当前规则选出的统一重量／次数、轮后休息和备注 |

普通动作／递减组的 `suggested*` 继续充当兼容性摘要，完整静态安排保存在 `setPrescriptions`；摘要不能反向覆盖逐组值。转换仍生成新计划项和成员身份，不复用来源计划的 `itemId` / `memberId`。

训练整体备注预填为计划整体备注，普通动作、递减组和超级组备注按现有单元归属复制。默认休息直接保留可选值：`nil` 跟随全局、`0` 关闭、正数为目标秒数；不从每组预计／实际休息推导。

超级组不增加字段，也不修改 `SupersetCreationSheet`、`PlanWorkoutBuilder` 或 `PlanWriteback` 的现有规则。它仍以各成员已完成正式记录的现有摘要作为后续统一安排，不按轮保存或回填不同值。

替代方案是读取原计划复制，或调用计划 Fork／复制的去重量路径；前者会补回未练动作并遗漏临时调整，后者会清掉用户自己本次实绩重量，因此均不采用。

### 4. 历史另存只创建新计划，完成页副作用留在完成页

历史路径的写入对象只有新 `WorkoutPlan`。不得对原 `Workout` 调用改名或 `markDirty()`，不得修改其 `planId`、来源分享字段、子树和备注；也不写来源计划、Team 分享版本或打卡摘要。表单回调只在创建成功后反馈结果。

现有完成页继续使用原入口和提示条件。它的保存后更新训练名称行为已写入主规格，本次只在 delta 中明确该行为属于完成页；若实现时提取创建公共逻辑，完成页的改名动作也必须留在该入口调用方，不能混进历史通用创建路径。无需为了历史入口合并两张表单。

另存计划默认自适应。所选历史只是静态模板的初始来源；后续详情预览、开始训练和完成回写继续遵循普通计划规则。存在优先级更高的历史时，动态「下次训练安排」可能不同于静态模板，不能为另存计划添加固定回放标记或强制严格模式。

### 5. 按普通计划处理持久化、失败和同步

在现有创建分支中使用可见的保存结果：提交期间屏蔽重复保存，只有 `ModelContext.save()` 成功才调用成功回调和关闭表单；失败时保留表单输入、显示错误并允许重试。失败重试应清理本次未成功的插入候选，避免留下额外计划；不通过整个共享上下文的无差别回滚丢弃其他编辑。

数据及同步约束直接落在现有实体上：

- 新计划沿用项目当前 UUID 生成方式，并持有独立计划项／成员身份；沿用 `localId/serverId/updatedAt/deletedAt/version/syncStatus` 信封。初始为 `pendingCreate`、`deletedAt == nil`、`version == 0`。
- 业务归属由当前登录用户和既有服务端鉴权确定，不以 Apple 等登录提供方标识作为计划身份；不改变用户与登录身份的分层。
- `forkedFrom`、`forkedFromShareVersionId`、`sharedToTeamId` 默认保持空，不把训练的来源关联复制为新计划的关系。
- 离线时先保存本地，再由现有计划同步队列上传；复用现有幂等键和 LWW。同步重试针对同一新计划身份，不再次执行历史转换或创建。
- 后续删除新计划沿用普通计划软删墓碑；删除任一原记录不级联影响新计划。不增加按组、按轮同步或合并。

服务端仍接收既有 `WorkoutPlanDTO.items` JSON，不新增 API、同步域、数据库列或 Flyway 迁移。

## Risks / Trade-offs

- [共用资格误放宽完成页提示] → 分别测试历史手动资格和 `personalPlanWorkoutDoesNotOfferSaveAsTemplate`，保留完成页 `planId` 与 `alreadySaved` 限制。
- [复用旧保存逻辑导致历史改名] → 新建参数只传值；验证原训练名称、来源关联、同步信封及来源计划在另存前后不变。
- [摘要或表单重建使逐组数据丢失] → 为不同重量／次数的普通组、多组不同 segments 的递减组增加转换及 JSON 往返测试；基础信息编辑不重建动作项。
- [保存失败仍显示成功或重试插入多份] → 对失败结果、连续提交和成功回调次数增加定向持久化测试；UI 断言失败时表单与输入保留。
- [自适应历史优先与所选旧训练不同] → 模式和预览继续使用普通计划现有说明与算法；验证静态初始值完整保留，不承诺后续固定复现某次旧训练。
- [超级组被错误纳入逐轮扩展] → 用各轮实绩不同的样例断言仍生成成员统一摘要，既有启动与回写测试作为兼容性检查。
- [原记录已引用失效的自定义动作] → 沿用普通计划的动作名称快照和不可开始提示，不修复或重建动作库引用。

## Migration Plan

1. 在 iOS 增加历史入口及普通新建表单初始值，补齐下述定向验证；后端与基础设施无需部署。
2. 不执行数据迁移或批量转换。用户每次明确另存后才产生普通新计划，现有计划、训练和 Team 数据不回填。
3. 回退客户端入口时，已生成的计划仍按普通 `WorkoutPlan` 展示、训练和同步，无需删除或补偿历史数据。

验证按 `docs/development.md` 执行：转换／持久化与兼容性使用定向单元测试，首页与日历入口使用相关 UI 行为断言；固定单个现有模拟器、串行运行。测试动作已包含编译，不额外重复 build。纯计划文档阶段只做 OpenSpec 校验与差异检查。

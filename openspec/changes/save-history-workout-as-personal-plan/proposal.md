# 历史训练另存为个人计划

## Why

用户希望把某次实际练出来的训练快速整理成可复用的个人计划，免去重新添加动作和录入每组重量、次数的操作。目前历史详情只有海报分享和删除入口，已有的完成页保存能力又排除了个人计划来源的训练，无法覆盖这一需求。

## What Changes

- 在自己的已完成历史训练详情 `…` 菜单中增加「另存为个人计划」，覆盖首页最近训练与历史日历共用的详情页；训练是否来自个人计划不影响这一手动入口。
- 将本次实际训练内容作为新建个人计划的预填值，复用普通新建计划的名称、备注、模式、分组和保存流程，默认自适应。
- 普通动作保留已完成热身组与正式组各自的重量、次数和顺序；递减组保留各已完成逻辑组及其有序内部组。跳过的动作与未完成组不带入。
- 超级组沿用当前转换规则：保留既有轮数、成员顺序、每个成员的一套重量与次数、轮后休息和备注；不增加逐轮预填或回写能力。
- 保存为独立、私有的普通 `WorkoutPlan`，一次性带入训练整体备注、动作备注和休息配置；不修改原训练、来源计划或既有 Team 快照。
- 区分历史手动另存与完成页默认提示的条件。完成页现有提示范围、来源计划回写回执及保存后更新训练名称的行为保持兼容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workout-tracking`：增加历史训练手动另存、新建表单预填、逐组内容转换与独立保存的要求，并明确现有完成页保存要求的适用范围。

## Non-goals

- 不扩展超级组数据模型、编辑界面、开始训练或自适应回写规则，不保存每轮不同的成员安排。
- 不恢复原计划的未练动作，不复制来源计划的备选动作，也不建立历史记录与新计划之间的持续关联。
- 不改造历史训练编辑、计划 Fork、Team 分享或成员打卡复制流程；不自动分享到 Team。
- 不新增后端接口、数据库迁移或同步域，不开展全量回归、性能分析或发版。

## Impact

- iOS：涉及 `WorkoutDetailView.swift` 的菜单与表单呈现、`PlanViews.swift` 中 `PlanEditorView` 的初始内容与保存反馈，以及 `WorkoutPlanTemplateFactory.swift` 的转换资格与内容复用。
- 兼容性：`WorkoutViews.swift` 内完成页保存入口仍使用现有提示条件与训练名称更新语义；不能直接把这些副作用带入历史另存。
- 数据：复用 `WorkoutPlan`、`PlanItem.setPrescriptions`、`PlanSupersetMember` 和既有计划分组排序、离线保存及 LWW 同步。
- 验证：扩充转换与保存的定向测试，补充首页／日历历史入口的 UI 行为断言；后端和基础设施无实现改动。

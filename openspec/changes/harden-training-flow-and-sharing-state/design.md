# Design

## Context

依据专项审查与当前工作树：S1可靠保存18/18、S2可读性15/15已完成，均不是全产品准发布结论。当前确认的具体实现：

- `WorkoutViews`、`PlanViews`、`TeamViews`三处冲突均将丢弃作为实心主按钮，显式取消隐藏。
- `TeamListView`先用空数组渲染无Team，再异步reload；`TeamCheckinHistoryModels`用未加载月份的空集合生成零统计。`WorkoutHistoryStore`已有`loadState`和`hasSnapshot`。首页已有`WorkoutHistoryReadyView`首次加载门控，但缓存读取失败不提示，历史入口也随门控隐藏；个人日历尚未消费这些状态。
- `ProfileView`的可见开关用`showsEstimates && bodyWeightKg != nil`，未设置体重却用原始`showsEstimates`显示红色必填。旧默认`showsEstimates=true`不能直接改为false，否则可能改变已有用户的显示选择。
- `InPlaceReorderPanel`的四类宿主均在`onDismiss`提交；保存函数部分仅展示错误而面板已关闭。主规格本来要求取消与禁止下滑，这属于实现修复。
- 胶囊使用固定`bottomInset=96`。S2默认字号截图已确认与首页CTA左侧相交；S2仅修触达与辅助功能动作，未解决避让。
- 后端V20与`TeamService.addMember`均将新成员分享和消息设为开启。主动分享页“仅自己可见”按钮仅dismiss，不撤回既有checkin。S0已校正产品与隐私页面仓库说明，线上页面尚未部署。

## Goals / Non-Goals

实现proposal与三个增量规格的可观察行为，保留现有原生导航、Paper外观及S1/S2保证。每项修复由隔离故障或实际手势验证，不把新测试方法未命中记为通过。性能修改限定为消费已有状态与小范围几何，不增加数据层或复杂缓存。

本change不将S0剩余长Requirement和未来多身份登录当作运行时改动，也不为收尾另建未经验证的新完成页面。正式后端、APNs、HealthKit、VoiceOver及多设备验收继续按专项后续批次处理。

## Decisions

### 1. 冲突动作复用公共弹窗，继续为主

在三个真正新建训练的守卫接入同一动作顺序：继续训练、危险次操作丢弃并开始、取消。复用`paperConfirmDialog`，若需区分次操作危险角色，只增加真实调用需要的参数。继续/取消不操作模型或休息；丢弃继续复用S1的原子替换路径，成功后才停休息。历史另存所得计划复用个人计划守卫，动作详情继续纯浏览。当前首页实际仅提供空白开始，未发现直接从历史再练的入口，本change不新增该功能。

不增加第二次丢弃确认或新会话框架：用户已经显式选择危险动作，多一层确认不改善保存正确性。

### 2. 加载状态来自读取事实，缓存保留

Team列表在视图层保留首次读取状态，非空已有内容独立于刷新状态；未成功且无内容时展示加载或失败重试，创建/加入仍可操作。取消任务不显示错误，也不把取消当作空集合。Team月份以`loadedMonths[month]`区分已加载，错误按请求月份处理，切月响应只写自己的缓存。

个人首页/日历直接消费`WorkoutHistoryStore.loadState/hasSnapshot`，不新增查询。日历壳只增加必要的内容状态输入，使统计、选中日抽屉和辅助功能一致；已有快照刷新时保留旧数据。不同来源保留各自数据和详情目标。

不引入全局通用加载框架：已有状态足够，本次问题是展示将未知误当为零。

### 3. 分享与取消文案反映真实可见性

创建/加入表单在提交前说明当前默认开启及关闭位置，不额外弹同意对话框。主动分享页改为取消本次选择，说明发送/更新与既有分享不受取消影响，保留原显式分享及Team内撤回流程。用户取消不调用删除或偏好接口，也不推送消息。

不把“取消”改造成批量撤回：这会扩大数据影响，并改变用户已保存的分享选择。

核对主规格时还发现S2新增的`TeamTodayMembersSheet`标题/关闭按钮与既有“拍一拍队友入口”契约冲突。本次恢复无额外标题的系统拖拽关闭，保留大字行与辅助功能escape；测试改为真实下滑关闭，不以新增关闭按钮的旧通过结果证明原契约成立。

### 4. 估算用实际可见状态表达用户选择

派生可用状态以有效体重和开关共同决定；缺少体重展示未设置/可选。开启动作携带显式启用意图，体重行携带编辑前的可见开关状态；保存按该意图明确保留开/关，取消不写。已有本地key、体重有效范围和估算计算链路保持不变。

不全局改变旧默认值，也不因填写体重就在所有来源隐式开启消耗估算。

### 5. 排序在完成时可靠提交，取消仅丢草稿

`InPlaceReorderPanel`复用公共Sheet标题，显式取消与完成，禁用下滑。四类宿主的onDismiss仅清理，不保存；完成调用可报告成败的提交函数，保存成功才关闭。仅变更当前存活项的排序，保留稳定身份和未参与排序项，避免丢失期间新出现的项。

提交前备份本次会修改的顺序、聚合结构与同步元数据；失败恢复这些字段并保留草稿。不得调用全局`modelContext.rollback()`清掉其它待保存训练输入。当前训练排序同时保持训练单元与动作顺序一致，但不改来源计划。复用`LocalModelCommit`与既有保存反馈，按需注入故障验证重试和取消。

### 6. 浮层用实测操作区域约束

优先复用现有GeometryReader与按值几何测量，把可用安全区域和底部主操作的实际区域传入胶囊定位。默认与左右吸附选取不相交的有效位置；尺寸变化后重新约束。相同几何不重复发布；拖动阈值、点击与辅助功能默认动作保留。无需更改训练状态、全局秒级观察或历史读取。

固定再加一个像素偏移不能覆盖大字号，因此不以加大96pt常量作为最终方案。

S5复核发现资料页同步组未提供避让锚点；仅补锚点后，信息较多的浮层仍可能盖住性别或默认休息。同步组、共用设置行及称呼按钮提供实测区域；资料页以及其它紧凑宽度的辅助功能字号使用44pt的既有训练图标，把空间让给表单。完整训练名、已进行时间与下一组信息继续用于无障碍朗读，点击和拖动沿用原逻辑。以当前可见按钮和性别文字逐一检查交叠，并复核截图，避免只把遮挡转移到另一处。此调整不压缩训练正文，也不增加全局观察或历史读取。

S6静置用例确认，原局部TimelineView只更新可见数字，外层辅助功能字符串停留在上次布局；紧凑分支同样缺少更新来源。将现有秒级TimelineView的范围覆盖单个胶囊内容，文字和辅助功能标签都消费同一个调度日期，保持几何约束与手势状态在原组件内。三类入口分别检查连续两个静置窗口，不通过点击或拖动触发刷新；同时复核历史读取次数及既有避让。系统语义查询通过不替代真实VoiceOver验收。

### 7. 收尾先测同次多结果，再修明确竞争

构造一次命中自适应回写、PR与徽章的隔离训练，记录结束前后弹层顺序、必要点击数与可离开路径；同时覆盖无计划训练另存、回写撤销、保存失败及慢历史读取。当前源代码通过两个异步任务分别请求PR和徽章呈现，优先在既有呈现协调处处理互斥与去重；只在回归证明竞争时修复，不把未知热点变成架构重写。

保留每项可选回执、奖励和导出功能，允许关闭；不让Team或网络成功成为本地收尾前提。

实际正常基线为计划回写→PR→徽章，依次关闭后可直接回首页，单次共6次点击。严格计划没有首个回写弹层，进一步复现了徽章关闭期间提前选中PR、随后旧关闭回调清掉PR内容的竞争。调度同时检查当前绑定与尚未清理的已呈现身份，等待旧弹层的onDismiss完成清理后再选下一项；复用现有状态，不增加延时或新队列。

回执关闭后无法重开，完成页补“查看计划更新”，历史详情的更多操作同步提供入口。仅在当前登录会话保留最近一次、按训练身份关联的回执；换账号或下次回写替换，不新增持久化实体。撤销前比较回写后的动作快照：后续动作编辑不匹配时保留当前计划并解释无法撤销，成功撤销后移除重开入口。

最大字号截图进一步确认旧回执的计划名与撤销按钮被省略、详情受固定行高挤压。回执复用公共自适应Sheet标题与操作区，正文独立滚动并完整换行；普通字号用实测标题和正文确定自然高度，大字使用large，不再以动作数量×72pt固定详情高度。

### 8. 数据与验证边界

不增加业务模型或服务端字段：身份三层、JWT Keychain、现有幂等键、同步信封、Workout聚合LWW及软删除语义均不变。新建/替换、排序、撤销仍走现有可靠提交与标脏路径，Team快照仍由服务端裁决。

UI测试扩展现有DEBUG隔离store和URLProtocol，延迟/失败/重试由可控响应驱动；不重置普通本地库，不对真实账号创建Team、分享、撤回或发消息。继续复用同一现有模拟器串行验证，测试镜像与实际运行UUID核对沿用S2已确认的安装缓存处理。实际VoiceOver及设备/性能证据单列。

## Risks / Trade-offs

- [四个排序宿主共享面板，但提交对象不同] → 分别验证取消、成功及故障重试；只恢复本次排序字段，不回滚其它修改。
- [新状态与旧内容同时存在] → 首次失败和缓存刷新失败分别测，未知统计、视觉与辅助功能使用同一事实。
- [默认分享说明可能过长] → 沿用S2自然高度与大字滚动，不用小字号截断，也不增加强制确认。
- [胶囊遇到狭窄可用区域] → 以实际边界选择有效候选，先保证主操作可达，设备矩阵继续独立验收。
- [奖励异步返回改变呈现时序] → 固定隔离数据与响应顺序验证互斥、去重、关闭后返回及原记录可用，不以截图代替操作。

## Migration Plan

无数据迁移。客户端正常替换即可，回滚恢复对应视图逻辑，已保存训练、计划和偏好无需转换。线上隐私页面源文案属于S0发布核对，不在此change执行部署。

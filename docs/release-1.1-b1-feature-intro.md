## 一句话摘要

本次版本补齐随 App 发布的本地动作演示图，并让训练计划、临时加组、休息计时和训练海报更贴近用户下一次真实训练。

## 面向测试用户的更新说明

以下内容只描述相对已发布版本 `v1.0-b21` 的最终用户可感知变化。

### 动作库与动作演示

- 动作库改为更紧凑的双列图片卡片，优先展示随 App 安装的本地动作演示图；没有专属图片时继续使用肌群图或文字占位，不依赖运行时联网下载。
- 当前候选包包含 193 张正式运行时动作图。225 个预置动作中，181 个已发布专属演示图，「器械上拉」已记录跳过并使用肌群图降级，其余 43 个功能性、热身拉伸或自重核心动作按规则使用现有展示方式。
- 新增「绳索直立划船」和「掌心向上哑铃侧平举」两项肩部预置动作。
- 核心动作名称进一步统一，包括「侧支撑」「负重俄罗斯转体」「下斜凳卷腹转体」「下斜凳卷腹」；原「卷腹」不再作为可新选的预置动作，但既有训练历史仍需保留。

### 计划中的下一次训练安排

- 计划动作展开后统一展示“下一次训练安排”，可直接看到下一次实际会采用的组数、重量、次数、热身组和递减组结构。
- 自适应计划会说明安排来自最近训练、计划预设、默认值还是当前保留值，页面展示与真正开始训练时采用的内容保持一致。
- 动作卡片默认收起，同一时间最多展开一张；低频操作集中到更多菜单，浏览长计划时更清楚。

### 训练中的历史预填与排序

- 临时新增普通组或递减组时，会优先带入同一动作、同一结构最近一次已完成的记录；普通组和递减组互不串用，未完成数据不会成为历史模板。
- 新建超级组时，会优先沿用相同动作组合的轮数和成员参数；没有同组合历史时，再分别参考各动作自己的最近记录。
- 训练中有两个及以上一级训练单元时即可进入排序，超级组会作为一个整体移动。

### 休息目标继承

- 训练中临时调整的休息目标会在本次训练内保留，下一组相同动作优先继承最近完成组的最终休息目标。
- “继续休息”会分别累计目标时长与实际休息时长，提前结束或自然结束都能保留最终目标，避免下一组退回旧值。
- 普通动作的“默认休息”会跟随训练数据保存，页面重建、最小化恢复或同步后仍可继续使用；超级组下一轮也会沿用相邻已完成轮次的休息目标。

### 训练海报与日历

- 训练分享海报不再只展示前 6 个动作；超过 6 个动作时改用紧凑双列布局，完整呈现本次训练内容。
- 修复在日历中选择相邻月份日期时，选中状态随月份切换跨网格跳动的问题。

## 内部技术变更

- 建立动作图母版、来源记录、运行时 manifest、覆盖率报告和严格校验流程；运行时只读取随包 JPG，不引入远程图片服务或新的运行时依赖。
- 动作库生成器增加防缩减门禁；当来源文档生成条目少于现有 manifest 时拒绝覆盖，避免静默删除已发布动作。
- `WorkoutUnit` 的默认休息时长作为可选字段写入现有 JSON 载荷；服务端继续按原契约透传，无需数据库 schema 或 API 变更。
- 训练组继续分别保存最终休息目标和实际休息时长，休息继承只在同一训练、同一动作或同一超级组邻近轮次内生效。
- 计划详情统一复用真实开始训练时的下一次安排推导逻辑，减少预览与实际训练结构不一致。
- 补充后端 JSON 透传测试，并固化动作图制作、审核和发版技能；这些变更不影响线上接口。

## 兼容性说明

- 本次不需要先发后端。现有生产后端可以同时服务 `v1.0-b21` 和 `v1.1-b1` 客户端。
- 新增的 `WorkoutUnit` 默认休息字段是现有 JSON 中的可选字段。旧客户端会忽略该字段，新客户端在字段缺失时继续使用动作默认值或全局默认值。
- 本地动作图、双列动作库、训练历史预填、休息继承、完整海报和日历修复都需要安装 `v1.1-b1` 客户端后生效。
- 预置动作下架或改名继续保留既有历史解析能力。「卷腹」停止新选但保留历史原名；`v1.0-b21` 已发布的「器械上拉」已恢复，当前无专属图时使用肌群图降级。
